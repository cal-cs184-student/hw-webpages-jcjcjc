Overview

We implemented path tracing that simulates realistic lighting by tracing rays from the camera into the scene. In Part 1 and 2, we implemented ray generation and scene intersection using bounding volume hierarchies. In Part 3, we implemented direct illumination. In Part 4, we implemented global illumination with both direct and indirect lighting as well as a Russian Roulette policy to determine termination of recursive bouncing light rays. Lastly, in Part 5, we implemented adaptive sampling to use a higher sampling rate on pixels that need it most, using a lower sampling rate for pixels that don't. The most interesting takeaway was seeing how each layer of the path tracer builds on the previous ones to produce a realistic image. For example, we started with zero-bounce emission, then added direct illumination (one-bounce), then computed indirect bounces to add soft color bleeding and lighten up the darkened shadows. It was cool to understand how each component contributed by itself, and then later see how they combine to create the final rendered scene.

Part 1: Ray Generation and Scene Intersection

For ray generation, we take the normalized image coordinates and map them onto the camera sensor in camera space. We do this by linearly interpolating across the sensor plane: the coordinates are scaled and shifted so that (0, 0) maps to the bottom-left corner of the sensor at (−tan(hFov/2), −tan(vFov/2), −1) and (1, 1) maps to the top-right corner. This gives us a point on the sensor at z = −1, which defines the ray direction in camera space. We then transform this direction to world space by multiplying with the c2w matrix and normalizing. The ray is created using the camera's world-space position as the origin and this direction, and we initialize min_t and max_t with nClip and fClip as the spec suggests.

To raytrace a pixel, we first initialized an accumulation vector. Then, we loop ns_aa times, and each iteration we sample a random offset within the pixel using gridSampler, add it to the pixel's corner coordinates, and divide by the image dimensions to normalize them. We pass these normalized coordinates to generate_ray, trace the resulting ray through the scene, and add the returned radiance to our accumulation vector. Once the loop finishes, we store the averaged result into sampleBuffer.

Triangle and Sphere Intersection Algorithms

We use the Möller–Trumbore algorithm for triangle intersection seen in lecture. We set up a linear system from the ray and triangle edges, then we solve for t, b1, and b2 using Cramer's rule. We ensure that a hit is valid by checking if t is in the ray's [min_t, max_t] range and the barycentric coordinates to satisfy b1 ≥ 0, b2 ≥ 0, and b1 + b2 ≤ 1. If we find a valid intersection, we update max_t and interpolate the vertex normals with the barycentric weights to get the shading normal.

For spheres, we plug the ray equation into the sphere equation, which produces a quadratic in t, also seen in lecture. Because a negative discriminant means the ray misses entirely, we short circuit the calculation there. Otherwise we get two roots and then we pick whichever is smaller and still falls in the valid [min_t, max_t] range. We then update r.max_t and the intersection data accordingly. The surface normal is calculated as the unit vector pointing from the sphere's center to the hit point.

Part 2: Bounding Volume Hierarchy

We construct the BVH recursively. At each step, we compute the bounding box of all the primitives in the current range. If the number of primitives is within max_leaf_size, we make it a leaf node and return.

Otherwise, we need to split. We pick the axis with the longest extent on the bounding box (whichever of X, Y, or Z is the widest) and use the midpoint of the bounding box along that axis as our split point. We chose the midpoint heuristic because it's relatively simple and doesn't require iterating over all the primitives to compute. We then partition the primitives in-place using iter_swap, so that primitives whose centroid falls below the midpoint get swapped to the front, giving us a mid iterator that divides the range into two groups. If all primitives happen to land on one side (which would cause infinite recursion), we just split the list in half. We then recursively build the left and right children by recursively calling construct_bvh on [start, mid) for the left child and [mid, end) for the right child.

Without BVH, rendering is very slow because every ray has to be tested against every single primitive in the scene. With BVH, we can skip large groups of primitives whose bounding boxes the ray doesn't hit, bringing the complexity down. For example, maxplanck went from 124.7160 seconds without BVH to 0.0612 seconds with BVH. Lucy went from 325.3210 seconds to to 0.0593 seconds, and the dragon went from 307.1177 seconds to 0.0540 seconds. On average, hich shows the BVH is doing its job well, achieving huges speedups.

Part 3: Direct Illumination

Uniform Hemisphere Sampling: For hemisphere sampling, we estimate the light arriving at a hit point by shooting rays in random directions over the hemisphere. For each sample, we get a random direction from hemisphereSampler, convert it to world space using o2w, and cast a ray from the hit point in that direction. If the ray hits something, we check if that object emits light. If it does, we plug everything into the reflection equation, which uses the BSDF value, the incoming light, the cosine term, and the pdf (which is 1/(2π) for uniform hemisphere sampling). Here, cosine(theta) is simply just the z direction of our sample because the surface normal is (0, 0, 1), so the dot product between surface normal and sample is just the sample's z value. After all the samples, we divide by the total count to get our Monte Carlo estimate.

Importance Sampling Lights: Instead of randomly sampling directions and hoping to hit a light, we loop through each light in the scene and sample directions directly toward it. For each sample, sample_L gives us the emitted radiance, the direction to the light, the distance, and the pdf. We first check if the light is behind the surface (if the local z-component of the direction is negative, we skip it). Then we cast a shadow ray toward the light, setting max_t to just before the light so we only detect blockers in between. If nothing is blocking the light, we compute the contribution using the reflection equation with the pdf from sample_L. For point lights we only take one sample since they always give the same result, and for area lights we average over ns_area_light samples.

Different numbers of rays: With just 1 light ray, the soft shadows are very noisy, as pixels look either fully lit or fully dark with a lot of grain. This is because lighting sampling only samples directions toward the lights, so every sample has a chance of contributing some bit of useful information.

Part 4: Global Illumination

To implement the indirect lighting function, we first initialize each camera ray depth to whatever the renderer sets the max_ray_depth parameter to. Inside the indriect lighting function, we first handle the base case of if the ray is 1, then return the radiance from one bounce. The one bounce radiance was calculated in earlier parts of this assignment, so we just call a function to determine this value. We sample a random bounce direction wi based on the BSDF, and and also find how likely that direction was (pdf) and the brdf_value of how much the surface scatters light in that direction. We convert wi to world space coordinates, then create a new ray with a decremented depth. If this new ray intersects with any objects in the scene, we then conduct Russian Roulette to see if we continue bouncing. We continue with a probability of 0.6 (cpdf), and terminate with a probability of 0.4. If a coin flip with heads probability of 0.6 is heads (or if this is the first indirect bounce since we always trace at least one indirect bounce regardless of Russian Roulette), then we continue. We calculate the bounce by recursively calling this indirect lighting function for the new ray and new intersection, multiplying by the brdf_value and cosine theta, and dividing by the pdf and cpdf. We add this to the one bounce radiance value and return. If we want unaccumulated bounces, we just return the bounce from the recursive call without the one bounce radiance added. Additionally, to estimate global illumination, we add the radiance from zero bounces and the radiance from the indirect lighting function, which accounts for at least 1 bounce of light.

Part 5: Adaptive Sampling

The algorithm to implement adaptive sampling is as follows: as we generate sample rays per an individual pixel, keep track of the sum of sample illuminances (s1) and sum of sample illuminances squared (s2) at every loop. Every so often, depending on the samplesPerBatch parameter that the renderer sets, check if the pixel has converged. To do this, use s2 an s2 to calculate the mean and variance of the n samples that we've generated so far. Then, compute I = 1.96 * standard deviation / square root of n. If I <= maxTolerance parameter * mean, then the pixel has converged and we can stop sampling. The effect is that areas with more variance like object edges and creases require high sampling rates (red) while low variance areas like flat walls need lower sampling rates (blue).
